# Production setup — Reign in Wealth Retreats

This update keeps the supplied **Next.js / SQLite / local media** application and its **cPanel Passenger** entry point. The canonical site is **https://reigninwealthretreats.com**; the HTTPS `www` origin is allowed for forms. No live keys, passwords, database or traveler data are included.

## 1. Install the source update in Codespaces

Extract this package outside your repository, such as `/tmp`. From the extracted update folder:

```bash
python3 install.py --repo /workspaces/Reign_in_Wealth_Retreats
python3 install.py --repo /workspaces/Reign_in_Wealth_Retreats --apply
```

The installer accepts the parent repository or its `reign-in-wealth-retreats` app folder. The first command is a dry run. The second verifies all payload checksums, backs up changed code and applies the update. It removes only unchanged original stock images listed in `obsolete-files.json`; customized versions are preserved.

The installer preserves `.env`, databases, media uploads, backups, dependencies and build output. It does not commit, deploy, run migrations or install dependencies. The included `app/` is a complete source copy. For a fresh installation use `--repo /path/to/empty/app --new --apply`.

In the app folder:

```bash
cd /workspaces/Reign_in_Wealth_Retreats/reign-in-wealth-retreats
npm ci --include=dev --no-audit --no-fund
npm run typecheck
npm test
npm run build
```

Keep your development `.env` in Codespaces. Prepare production `.env` on the actual production host. After reviewing the changes, commit and push the source, including `.env.production.example` and the new scripts. Your existing parent `.cpanel.yml` remains in place.

## 2. Prepare the production environment

Use your existing Node.js **22.23.5 or newer** hosting environment. After copying the updated source into the live application directory, run:

```bash
export PATH="/opt/cpanel/ea-nodejs22/bin:$PATH"
cd /home/reigninw/reign-wealth-retreats-app
node scripts/production-env.mjs --admin-email YOUR_CONTROLLED_EMAIL
node scripts/production-env.mjs --admin-email YOUR_CONTROLLED_EMAIL --apply
```

Use your actual configured app path if it differs. Replace `YOUR_CONTROLLED_EMAIL` with your administrator email; this does not create a mailbox. Omit `--admin-email` when retaining an existing real admin email. Keep the app outside `public_html`.

Without `--apply`, preparation is a preview. Applying it sets the HTTPS domain, `NODE_ENV=production`, `DEV_PREVIEW_MODE=false`, and `DEBUG_ORIGIN=false`. It preserves existing credentials, provider keys and database/media/backup paths. Missing paths receive absolute defaults in the app directory; existing data is never moved.

A missing administrator password is generated securely; save the displayed password privately. Only its scrypt hash is stored. A missing cron secret is generated too. An existing `.env` is backed up as `.env.backup.*` before changing it, and the file receives mode `0600`.

`app/.env.production.example` includes every production setting. Do not put a plaintext password in `ADMIN_PASSWORD_HASH`. Use the setup command for the correct format. Existing `.env.local`, `.env.production`, `.env.production.local`, and cPanel environment variables can override `.env`; review any overrides reported by the command.

## 3. Add the provider settings you control

| Variable | Value | Needed for |
| --- | --- | --- |
| `ADMIN_EMAIL` | Your controlled email address | Admin login |
| `ADMIN_PASSWORD_HASH` | Generated by setup | Admin login |
| `CRON_SECRET` | Generated by setup | Protected background jobs |
| `STRIPE_SECRET_KEY` | Your Stripe `sk_live_...` key | Live paid reservations |
| `STRIPE_WEBHOOK_SECRET` | The endpoint's `whsec_...` signing secret | Verified payment events |
| `RESEND_API_KEY` | Your Resend API key | Outgoing email and traveler login links |
| `EMAIL_FROM` | Sender on your verified Resend domain | Outgoing email and traveler login links |

Public pages work without Stripe or Resend. Without Resend, outgoing email stays queued. Live paid reservations require the Stripe settings. This package does not claim those accounts are configured.

Stripe webhook URL: `https://reigninwealthretreats.com/api/payments/webhook`.

Use the events already handled by this app: `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `checkout.session.expired`, and `charge.refunded`. Keep all keys server-side without a `NEXT_PUBLIC_` prefix.

## 4. Build and restart Passenger

From the production app directory:

```bash
npm ci --include=dev --no-audit --no-fund
npm run check:production
npm run build
node scripts/cleanup-legacy-images.mjs
mkdir -p tmp
touch tmp/restart.txt
```

Use `app.js` as Passenger's startup file. It sets the app-root working directory and production mode. The cPanel route uses the full `.next` build and installed dependencies, not the Docker-only standalone `server.js`. The image cleanup removes only unchanged original stock files and first saves recovery copies under `backups/legacy-stock-assets/`; customized files are retained.

Future cPanel Git deployments run the updated `deploy/cpanel-deploy.sh`: copy source, validate the production environment, build, then touch Passenger's restart marker. Prepare the production environment once before that validation gate. The Git checkout must be clean; use Update from Remote, then Deploy HEAD Commit.

For a check that also requires live payment and email configuration:

```bash
npm run check:production -- --require-integrations
```

The check uses Next.js's environment precedence. It verifies setting values and writable paths, not DNS, TLS certificates, provider account status or live delivery. Confirm valid HTTPS for root and `www`; then verify `/api/health`, gallery, `/admin`, a traveler email and the intended booking/payment flow on your host.

## 5. Jobs, backups and rollback

`npm run jobs` processes pending email jobs. Use your existing scheduler with the same Node PATH and app working directory. `npm run backup` makes a consistent SQLite copy and media backup. Keep off-server copies according to your existing backup policy. Do not put `.env`, databases or backups under `public/` or `public_html`.

The installer prints an exact code-backup path. To preview and apply rollback:

```bash
python3 install.py --repo /workspaces/Reign_in_Wealth_Retreats --rollback /EXACT/PRINTED/BACKUP/PATH
python3 install.py --repo /workspaces/Reign_in_Wealth_Retreats --rollback /EXACT/PRINTED/BACKUP/PATH --apply
```

Rollback restores overwritten code and original images and removes new files. Runtime data remains untouched. It refuses to overwrite files changed again after installation. Rebuild/redeploy after rollback if the update was already deployed. Code backups and the separate `.env.backup.*` files cover different changes. The existing copy/build deployment is not a zero-downtime release-switching system.
